- (decision) AD-1 Design Paradigm: Layered Architecture. Four layers (bottom→top): Input System (foundation, independent), Data Definition (pure data, no behavior: Move Data + Gatling Tables), Engine (Frame Data Engine + Combo Exec, depends on lower layers), Presentation (Training Mode UI, read-only consumer). Dependency direction: downward only. Same-layer modules must not directly depend on each other — cross-module needs go through the layer below. Frame Data Engine is the single source of truth for cancel window / timing signals.
- (version) Stack: Godot 4.x (C#, Mono/.NET), Godot UI (Control nodes), System.Text.Json (built-in .NET, no external dependency). No additional third-party dependencies identified for V1.
- (decision) AD-2 Structural Seed: directory layout — Scripts/Framework/{Input, Data, Engine/FrameData, Engine/Combo, UI/Training, Core}. Namespace: FTG_Framework.{layer}. Input and Data at bottom (no upward deps), Engine in middle (depends on Input + Data), UI at top (depends on all). Core shared by all layers (interfaces, base types).
- (decision) AD-3 Communication: Event-driven via centralized Event Manager (independent infrastructure, not owned by any module). Modules publish and subscribe through the Event Manager. No direct cross-module method calls between Engine modules. Training UI subscribes to all events as read-only observer.
- (decision) AD-4 Frame update order: Input events are processed first (InputReceived) before any other event in the same frame. Execution order per frame: Input System → Frame Data Engine → Combo Exec → Training UI. Combo Exec judges cancel eligibility based on having received CancelWindowEntered but not yet CancelWindowExited.
- (decision) AD-5 Event Manager: Singleton class, pure C#, lives in Core namespace. Not coupled to Godot scene tree or Node signals. Modules obtain the singleton reference to publish/subscribe. Event dispatch is ordered per AD-4 frame order.
- (decision) AD-6 Data ownership: Data layer (Data namespace) loads and holds all move definitions, Gatling tables, and configuration at runtime. Data objects are read-only after load. Engine layer reads via Data layer's public query API; Engine never holds or caches its own copy of data definitions. JSON is the canonical serialization format (loaded via System.Text.Json at startup).
- (decision) AD-7 GameLoop: Thin Godot autoload node bridges _Process to EventBus. Responsibilities: (1) call EventBus.ProcessFrame() each _Process, dispatching events in AD-4 order; (2) advance Input System frame counter; (3) no game logic. The GameLoop is the ONLY Godot Node in the framework core — all other modules are pure C# objects.
- (decision) AD-8 Error handling: Invalid input (malformed JSON, illegal move data, impossible frame timing) causes startup crash with descriptive error message. Fail-fast strategy — no silent fallback, no runtime recovery for data errors. Gameplay errors (e.g., move priority conflict) logged as warnings, framework picks the highest-priority resolution (per FR-5 default).
- (constraint) Conventions: C# standard naming (PascalCase types/methods/properties, camelCase locals/parameters, _camelCase private fields). JSON via System.Text.Json. Modules expose public APIs through interfaces defined in Core namespace. Data objects are immutable after construction.
- (event) Spine finalized. 8 ADs, 12-event catalog, 15 FR mapping, 8 deferred items. Reviewer gate skipped per user request. Ready for epic/story breakdown.
