- (decision) Executive Summary drafted and approved. Skeleton/muscle metaphor chosen. Scope: Godot 4.x C#, local-only, open source. Ambitious positioning: SF to BB/UNI all supported.
- (decision) Problem section drafted and approved. Developer's journey from happy first 6 months to hitting infrastructure wall. Key pain points: frame data visualization, input leniency, everyone rewriting same wheels. SF6 training mode as gold standard.
- (decision) Solution section drafted and approved. Key points: training mode as first-delight, modern input system out-of-box, frame data engine, state machine tools + example, Gatling registration. Explicit exclusions: full combo system (damage scaling, infinite prevention, hitstun chains), art/animation, balance, level design.
- (decision) What Makes This Different drafted and approved. Input system is the single most differentiating feature (heart). Training mode is second (killer feature for DX). UFE2 is the closest alternative but Unity-only, closed-source. Moat: Godot-native, open-source, C#, built from FG dev pain points.
- (decision) Who This Serves drafted and approved. Primary: Godot FG devs. First user: author (dogfooding). Mod community: nice bonus but not a design target. Final brief will be output in English.
- (decision) Success Criteria drafted. Top priority: dogfooding pass (baseline) and external adoption (key milestone). Secondary: community contributions, FGC recognition, long-tail reference value for modders.
- (decision) Scope section drafted. V1: Input System + Frame Data Engine/Training Mode + Combo API (Gatling registration, cancel windows). Explicitly deferred: state machine, hitbox, replay, object pool. Forever out: networking, Godot 3.x, full combo logic, art/animation/balance/levels.
- (decision) Vision section drafted and approved. 3-year vision: FTG Framework becomes the default recommendation for Godot FG devs. Small contributor circle, multiple shipped games in diverse styles. Not a UFE competitor - a lean foundation.
- (event) Addendum created with downstream details: UNI combo model, dual-timeline input architecture, per-move leniency granularity, buffer timing rationale, SF6 training mode feature set, module priorities.
